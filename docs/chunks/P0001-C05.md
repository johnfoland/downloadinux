# Chunk P0001-C05 — Structured health checks

**Source:** project [P0001](../projects/P0001-portable-config.md), delivery
item D4 (all of it), plus findings 1 and 7 of the P0001-C04 review (issues
#23 and #21). Authority: [target design](../target-design.md) *Health checks*
(all, and "Pinned for P0001-C05"), *Migration* ("Pinned for P0001-C05"),
*Host application* (exit status, OS failures, "Commands in the container"),
*Container contract* (the mount table); DEC-12, DEC-17, DEC-21, DEC-22.

**Goal:** `dlx doctor` returns the structured health result of DEC-12: an
ordered list of checks with stable IDs, statuses, summaries, and fixes, as
text or as JSON, exiting 1 when any check fails. It tells a missing mount
from an unwritable one, skips VPN checks with the VPN off, and never prints
a secret or a cookie value. `just doctor` becomes its wrapper, and the gate's
smoke test runs it in the VPN-off container. With D4 done, D5 (setup flow,
docs, and migration proof) is what remains of Stage 1.

## Kickoff notes

- **The check list is pinned row by row** (*Health checks*, "Pinned for
  P0001-C05"): IDs, order, conditions, summaries, and fixes. Build the table,
  not the old recipe; where they differ, the table wins (DEC-22).
- **Skips have an order**, first match wins. Read that bullet twice; the
  tests drive each arm.
- **Once the settings and credentials have loaded, nothing ends `doctor`
  early.** A missing `docker`, an unreadable jar, a non-JSON ipinfo body:
  each is a check's status, never a traceback or an `error:` line. Loading
  itself fails as in every command (exit 2 invalid, exit 1 unreadable).
- **Secrets:** the token, cookie values, and `nordvpn account`'s output (it
  holds the account's email) appear in neither view. The test plants fake
  values and greps both outputs for them.
- Unit b builds the model and host checks; c adds the container checks; d
  the VPN checks, the wrapper, and the smoke test. Each unit's `doctor`
  lists only the checks built so far.

**Review-checklist entries this chunk is likely to trip:**
`review-checklist §1`: `doctor` stats and reads files and starts `docker`;
here an OS failure becomes a check's `fail`, not exit 1, except where the
pinned text says otherwise.
`review-checklist §2`: cause failures for real (an empty `PATH` for a
missing `docker`, `chmod 000` for an unreadable jar, a real loose-mode
credentials file), not by raising by hand.
`review-checklist §3`: the jar, `nordvpn` output, and the ipinfo body are
parsed; malformed input of any shape is a status, never a traceback.

**Read first:** target design *Health checks* (all), *Migration* ("Pinned
for P0001-C05"), *Host application* ("Commands in the container, pinned for
P0001-C03"); DEC-12, DEC-17, DEC-22; the current `doctor` recipe,

**Preconditions:** P0001-C04 accepted and merged (pull request #19);

### P0001-C05-b — The result model, `doctor [--json]`, and the host checks
**Build:**
- A package module for the result (suggested `src/downloadinux/health.py`):
  a check (`id`, `status`, `summary`, optional `fix`), the four statuses,
  and the result (`ok` false exactly when a check failed) (*Health checks*;
  DEC-12).
- `operations.doctor` and the `doctor [--json]` subcommand: settings loaded
  as every command does (configuration error, exit 2), then the checks in
  pinned order; the human view and `--json` per the pinned bullets; exit 1
  on any `fail`, else 0.
- The host checks, per their table rows and the jar-reading bullet:
  `config.file`, `credentials.file`, `credentials.token`, `paths.downloads`,
  `cookies.jar`, `cookies.instagram`, `cookies.youtube`,
  `downloads.user_agent`, `docker.daemon`, `container.running`, with their
  skip rules. `downloads.user_agent` reuses `useragent`'s lookup through its
  `CHROME_PLIST` constant. `docker.daemon` uses the injectable capture with
  the CLI's own environment.
**Tests:** through `cli.main` with fake captures and real files under
`tmp_path`: every row's `ok` and non-`ok` arms, asserting `id`, `status`,
`summary`, and `fix` (or its absence) per the table; the order of the ten
IDs; `ok` and the exit status (0 with only warns and skips, 1 with one
fail); an invalid settings file exits 2 with no check list. A credentials
file at 0644 fails with `chmod 600 <path>`; at 0600 and 0400 it is `ok` with
the mode in the summary; absent it is `skip`. The token: `set`, `malformed`
(fail with the VPN off too), `unset` with the VPN on (warn) and off (skip).
A jar: missing, the entrypoint's placeholder (comments only), a cookie line
with six fields (not a cookie), an `instagram.com` `sessionid` behind
`#HttpOnly_` (present), `.www.youtube.com` `SAPISID` (present),
`notinstagram.com` `sessionid` (absent), non-UTF-8 bytes in a value (still
read), and `chmod 000` (fail naming the path; jar-site checks `skip`). The
user-agent: Chrome matching a real fixture plist, behind it, not Chrome, and
no host plist. `docker.daemon`: exit 0 with the version, exit 1, and a real
empty `PATH` (`docker: <reason>`, `container.running` `skip`, exit 1, no
traceback). `container.running` not running (fail, `dlx up`). Neither view
contains the fake token or a planted cookie value. The human view: the marks, the six-space `fix:` line,
no colour when standard output is not a terminal.
**Done when:** the tests pass and the gate passes.

**Tests:** the whole argv of each check's Compose call (the configured

`mount.downloads.writable`, `mount.config.mounted`, `mount.config.readonly`,

**Done when:** the tests pass and the gate passes.

## Notes for the executor

- Fake captures keyed on the command after `exec -T -u dl downloadinux` keep
  the container tests readable; assert the whole Compose argv in one test
  per check rather than in every test.
- `mountpoint -q` prints nothing for a missing path or a non-mount; `test
  -w` on a read-only bind is false for `dl`, which the smoke test already
  relies on.
- The smoke test's `up` needs the CLI's `--set` overrides the script already
  builds; `up` refuses without `paths.downloads`, which the script creates.
  The container from `up` keeps running until the trap's `down -v`.
- On the maintainer's macOS host the smoke run's `downloads.user_agent` may
  warn (host Chrome newer than the default): a warn is not a failure, and the
  smoke assertion does not name that check.
