# Chunk P0001-C05 — Structured health checks

**Source:** project [P0001](../projects/P0001-portable-config.md), delivery
item D4 (all of it), plus findings 1 and 7 of the P0001-C04 review (issues
#23 and #21). Authority: [target design](../target-design.md) *Health checks*
(all, and "Pinned for P0001-C05"), *Migration* ("Pinned for P0001-C05"),
*Host application* (exit status, OS failures, "Commands in the container"),
*Container contract* (the mount table); DEC-12, DEC-17, DEC-21, DEC-22.

**Goal:** `dlx doctor` returns the structured health result of DEC-12: an
ordered list of checks with stable IDs, statuses, summaries, and fixes, as
text or as JSON, exiting 1 when any check fails. It tells a missing mount
from an unwritable one, skips VPN checks with the VPN off, and never prints
a secret or a cookie value. `just doctor` becomes its wrapper, and the gate's
smoke test runs it in the VPN-off container. With D4 done, D5 (setup flow,
docs, and migration proof) is what remains of Stage 1.

## Kickoff notes

- **The check list is pinned row by row** (*Health checks*, "Pinned for
  P0001-C05"): IDs, order, conditions, summaries, and fixes. Build the table,
  not the old recipe; where they differ, the table wins (DEC-22).
- **Skips have an order**, first match wins. Read that bullet twice; the
  tests drive each arm.
- **Once the settings and credentials have loaded, nothing ends `doctor`
  early.** A missing `docker`, an unreadable jar, a non-JSON ipinfo body:
  each is a check's status, never a traceback or an `error:` line. Loading
  itself fails as in every command (exit 2 invalid, exit 1 unreadable).
- **Secrets:** the token, cookie values, and `nordvpn account`'s output (it
  holds the account's email) appear in neither view. The test plants fake
  values and greps both outputs for them.
- Unit b builds the model and host checks; c adds the container checks; d
  the VPN checks, the wrapper, and the smoke test. Each unit's `doctor`
  lists only the checks built so far.

**Review-checklist entries this chunk is likely to trip:**
`review-checklist §1`: `doctor` stats and reads files and starts `docker`;
here an OS failure becomes a check's `fail`, not exit 1, except where the
pinned text says otherwise.
`review-checklist §2`: cause failures for real (an empty `PATH` for a
missing `docker`, `chmod 000` for an unreadable jar, a real loose-mode
credentials file), not by raising by hand.
`review-checklist §3`: the jar, `nordvpn` output, and the ipinfo body are
parsed; malformed input of any shape is a status, never a traceback.

### Findings

1. `mount.config.readonly` reports `/config is read-only`, `ok`, when
   `/config` is not a mount point: on the maintainer's container `/config`
   is absent, so `test -w` fails for that reason (`health.py:285`, the
   report's own manual run shows `mount.config.mounted fail` beside
   `mount.config.readonly ok`). The code follows the pinned table; the table
   was wrong, the reason DEC-22 gives for skipping `writable` applies to
   `readonly` too. Follow-up. DEC-22 amended and *Health checks*' skip rule
   extended in this review with the maintainer's approval; the code and its
   test are scheduled as P0001-C06-a. The class is `brief-checklist §5`
   (new).
2. `vpn.connected` and `vpn.killswitch` read `nordvpn` output only from a
   run that exits 0, `connected` without a location renders as `connected`,
   and a `Kill Switch:` value other than `enabled`/`disabled` is `unknown`
   (`health.py:386–418`). None of the three was in the doc, and the report
   listed no reading. The code's readings are the sensible ones and change
   nothing observable for real `nordvpn` output; the doc was incomplete.
   Note. Fixed in this review (*Health checks*, the `nordvpn` paragraph).
3. Every `test_doctor.py` test that does not take the `chrome_plist` fixture
   reads the host's real Chrome plist through `useragent.CHROME_PLIST`. No
   assertion depends on it today, but the suite reads host state. Note.
   Scheduled as P0001-C06-a.
4. The smoke test asserts `ok` for whichever `mount.*` and `tools.*` checks
   are present, so a result missing them would pass that loop
   (`scripts/smoke.sh:66`); the unit tests pin the IDs, the smoke test does
   not. Note. Scheduled as P0001-C06-a (assert the exact ten IDs).
5. `cookies/README.md` says `just doctor` "tells you the truth about whether
   you're actually logged in", against *Health checks* ("none claims a login
   is valid"); README.md's wrapper list now omits `status`, which is still a
   wrapper. The first predates this chunk (D5 owns `cookies/README.md`).
   Note. Scheduled as P0001-C06-c.
6. The human view's colour arm has no test (the brief asked only for the
   no-terminal arm). Checked by hand above. Note; no action.
7. Unit d's CI run (`583fe97`) was still running when the report commit
   landed on it; it finished green, and the report commit changes only the
   chunk file. Note.
