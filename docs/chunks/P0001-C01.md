# Chunk P0001-C01 — Package, settings model, and `config` commands

**Source:** project [P0001](../projects/P0001-portable-config.md), delivery
item D1. Authority: [target design](../target-design.md) *Host application*,
*Configuration and paths*, and *Migration*, including their "pinned for
P0001-C01" lists; DEC-7, DEC-8, DEC-11, DEC-13.

**Goal:** the repo gains the `downloadinux` Python package (entry points
`downloadinux` and `dlx`) with its settings model and the commands that
create, inspect, and migrate configuration: `init`, `config show [--json]`,
`config set-token`, and `config import-env`. Nothing drives Docker yet. Every
later P0001 item computes paths, the Compose project, and the VPN environment
from this settings model, so it comes first. `just check` gains a pytest step
and CI installs uv to run it.

## Kickoff notes

- **Your real files are next door.** This checkout has a real `.env` (with a
  live NordVPN token) and a real `cookies/cookies.txt`, and `import-env`
  defaults to that `.env`. No test may read either, or touch the real `~`:
  unit a's autouse fixture points `HOME` and every `XDG_*` at `tmp_path` and
  clears `DOWNLOADINUX_CONFIG`, and every `import-env` test passes `--env`
  with a fixture file. The fake token in fixtures is a made-up 64-hex string.
- **Never print the token**, including in an error about a malformed one
  (print its length). Tests assert the fake token appears in no stdout or
  stderr, for every command that handles it.
- **The pinned lists are the spec.** Target design *Host application*,
  *Configuration and paths*, and *Migration* each end with a list "pinned for
  P0001-C01": exit codes, `--set` parsing, `config show`'s JSON, the `.env`
  mapping table, `--force` semantics. Build those; if one looks wrong, say so
  in *Doc inconsistencies found* rather than improvising.
- **One schema.** Defaults, types, validation, `config show` order, and
  `init`'s starter file should all come from one table of settings, so adding
  a setting later is one edit.
- Unit b is the largest; c and d build on its loader and writer.

### P0001-C01-b — Settings model and `config show`
**Build:**
- Settings locations: XDG resolution (unset, empty, or relative → the `~`
  defaults), the settings file chosen by `--config`, then
  `DOWNLOADINUX_CONFIG`, then the default; `credentials.toml` beside it
  (*Configuration and paths*, table and pinned list; DEC-8).
- The schema of every Stage 1 setting with type and default, including the
  computed defaults (`paths.state`, `paths.cookies`, `container.uid`,
  `container.gid`, `container.timezone` from `/etc/localtime`, the path
  injectable for tests).
- Loading with `tomllib`, validation, and precedence `--set` > file >
  default, recording each setting's source (`default`, `file`, `override`).
  Validation per *Configuration and paths*: unknown table or key, wrong type,
  relative path after `~` expansion, `technology` outside
  `openvpn`/`nordlynx`, `--set` without `=`; the string-setting rule for
  `--set` values. Errors name the file (or `--set`) and the key, and exit 2.
- Credentials loading (`[nordvpn] token`), with the token state `set`,
  `unset`, or `malformed`.
- Mount mappings: `/downloads` ← `paths.downloads` (rw), `/config` ← the
  checkout's `presets/` (ro), `/state` ← `paths.state` (rw), `/cookies` ←
  `paths.cookies` (rw), each with `exists`.
- `config show` and `config show --json`, exactly as the pinned list
  describes (text lines and JSON shape, schema order, file paths marked
  missing).
**Tests:** precedence across all three layers for at least one setting of
each type (string, path, integer, boolean); `XDG_*` set, unset, empty, and
relative for each of the three; `--config` beats `DOWNLOADINUX_CONFIG` beats
the default, a relative `--config` resolves against the working directory,
and a missing explicit file loads defaults; a downloads path with spaces
survives load and both `config show` forms intact; one test per validation
error asserting the message names the key and the file (or `--set`) and the
exit status is 2; `--set vpn.server=123` yields the string `123` and
`--set container.uid=abc` is a type error; timezone from a symlinked fake
`localtime`, a non-symlink, and a target without `zoneinfo/`; `config show
--json` parses, lists all settings in schema order with sources, the four
mounts in order, and the token as `set`/`unset`/`malformed`, and neither form
contains a fake token's value; a missing `paths.downloads` is reported, not an
error; global options work before and after `config show`.
**Done when:** all of the above pass and `dlx config show` runs from outside
the checkout after `uv tool install --editable .` (manual check, recorded in
the report).

### P0001-C01-c — `init` and `config set-token`
**Build:**
- An atomic writer for the settings and credentials files (temporary file in
  the same directory with the final mode, then rename), using `tomlkit` so
  an existing file's comments survive (*Host application*, pinned list).
- `init` per *Configuration and paths*' pinned list: the starter file with
  every setting, computed defaults commented out, `--set` values written in;
  creates the parent directory; refuses with exit 1 if the file exists.
- `config set-token [TOKEN]` per the pinned list: argument, else hidden
  prompt on a terminal (`getpass`), else one line of stdin; validation (64
  lowercase hex); credentials file written at 0600, its directory created.
  It only stores: logging in to a running container is D2.
**Tests:** `init` then `config show --json` reports every setting at its
default with written keys sourced `file`, and VPN off; `init --set
paths.downloads="/tmp/My Drive"` writes and reloads that value; a second
`init` exits 1 and leaves the file byte-identical; `set-token` by argument and
by stdin each produce a 0600 file that loads as `set`, including when an
existing credentials file was 0644 (the result is 0600); a malformed token
exits 1, writes nothing, and prints its length but not its value; re-setting
the token keeps a comment the user added to the credentials file.
**Done when:** the tests pass and no output of either command contains a
token value.

### P0001-C01-d — `config import-env`
**Build:** `config import-env [--env PATH] [--force]` per *Migration*
(including its pinned list) and DEC-13: `.env` parsing; the key mapping
table with its conversions; `vpn.enabled = true`; the settings file written
as `init`'s starter file with imported values (`--set` on top); the
credentials file only when a token imports; a malformed token warned and
skipped; the overwrite refusal checked before any write; the jar copy from
`cookies/cookies.txt` beside the `.env` into the effective `paths.cookies`
(directory 0700, jar 0600, an existing destination kept even with
`--force`); the summary of imported settings, the token as `set`, and the
keys not imported (`USERNAME` among them).
**Tests:** a fixture `.env` exercising comments, blank lines, `export `,
both quote styles, every mapped key, `USERNAME`, and an unknown key produces
a settings file whose `config show --json` shows each mapped value sourced
`file` and `vpn.enabled` true, a 0600 credentials file with the fake token,
and the jar copied with modes 0700/0600; the fake token's value appears in no
output; `NORDVPN_AUTOCONNECT=yes` (and an unknown killswitch value) exits 2
naming the file and key, writing nothing; a malformed token warns with its
length, writes no credentials file, and exits 0; with an existing settings
file, and separately an existing credentials file, the command exits 1 and
writes nothing, and `--force` overwrites both but keeps an existing
destination jar; a missing source jar is reported and the import still
succeeds; `.env` and the source jar are unchanged afterwards.
**Done when:** the tests pass; README.md describes the host CLI as it now
stands (see *Out of scope* for the limit).

## Notes for the executor

- A suggested shape: `cli.py` (argparse, `main`), `settings.py` (schema,
  locations, load, validate, overrides), `credentials.py`, `files.py` (atomic
  write, starter template), `migrate.py` (`import-env`), `checkout.py`. Keep
  operations callable without argparse (they take arguments and return data
  or raise), since the TUI will call them; the CLI only parses and prints.
- README.md: add a short section, near the top of *Command reference*, on
  installing the host CLI (`uv tool install --editable .`) and the four
  commands, saying plainly that they manage the new config files and that
  the `just` recipes still run from `.env` until later Stage 1 chunks land.
- `uv.lock` must be regenerated by uv, not hand-edited; `--locked` in the
  gate fails if it is stale, which is the point.
- `tomllib` gives `int` for TOML integers and `bool` is a subclass of `int`:
  a boolean in `container.uid` must still be a type error.
