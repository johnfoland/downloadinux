# Chunk P0001-C03 — Container commands, login on set-token, and D2's close

**Source:** project [P0001](../projects/P0001-portable-config.md), delivery
item D2 (the rest), plus findings 1 and 2 of the P0001-C02 review.
Authority: [target design](../target-design.md) *Host application*
("Commands in the container, pinned for P0001-C03", and the C02 "Docker
invocation" list it builds on), *Migration* ("Pinned for P0001-C03,
completing D2's wrappers"); DEC-11, DEC-16.

**Goal:** every D2 command exists. `dlx shell`, `dlx vpn …`, and
`dlx servers …` reach the configured project's container through the
computed invocation, `dlx config set-token` logs a running VPN container in
without the token ever touching a host argument list, and the `shell`,
`vpn`, `servers`, and `status` recipes are wrappers over them. The NordVPN
server ranking moves into the package, so `scripts/servers.py` and its gate
step go. `just doctor` stops depending on `.env`, and a failed settings
write names the settings file. With the two-project manual check recorded,
D2 is done and D3 (presets) is next.

  and the running check need a command's stdout; extend the injectable
  runner (or add a capturing sibling) so tests still start no process. Keep

  Relabel `N/7` and update AGENTS.md *Commands*; CI runs `just check`, so
  the workflow does not change.

### Doc inconsistencies found

1. **The pinned refusal hint can revoke the token being stored.**
   *Host application*'s C03 list says a refused login tells the user that
   a daemon already logged in needs `dlx vpn logout` first. The image's
   NordVPN (5.4.0) documents `logout` as revoking the current access token
   unless you pass `--persist-token`. A logged-in daemon refuses even the
   token it already uses (seen live). So for someone re-storing their
   working token, following the hint revokes that token, and the next
   login is refused again.
   Implemented as written. README tells you to use `just vpn logout
   --persist-token` when the daemon's token is the one you are storing.
   Filed as #17 with two options. The planner should decide whether the
   hint or DEC-16's handling of "already logged in" changes.
2. **"In no environment when the container is stopped."** The kickoff
   notes say the fake token is in no environment when the container is
   stopped ("nothing runs then"). But the running check does run, and
   under C02's invocation contract every VPN-on Compose call carries
   `DOWNLOADINUX_NORDVPN_TOKEN`; stripping it would make Compose warn about
   an unset variable in `vpn.yaml`.
   Implemented per the C02 contract. The test asserts the only call is the
   `ps` check, without the login's `NORDVPN_TOKEN`. The planner should
   confirm that reading.
3. **target-design named the deleted script.** The servers text named
   `scripts/servers.py`, which the unit b Done-when grep rules out once
   the script is gone. I fixed the doc to say "the old script" and to
   name `downloadinux.servers`.

### Findings

1. **The pinned refusal hint revokes the token** (report, *Doc
   inconsistencies* 1; issue #17). The doc was wrong: a logged-in daemon
   refuses every login, and plain `nordvpn logout` revokes the token it
   held, so following the hint while re-storing the working token leaves
   it revoked. Decided as DEC-19: the hint becomes
   `dlx vpn logout --persist-token`; *Host application*'s C03 list is
   corrected here. Severity follow-up; scheduled as P0001-C04-a, which
   closes #17.
2. **The kickoff note overstated the token rule** (report, *Doc
   inconsistencies* 2). The brief was wrong, the code right: under C02's
   contract every VPN-on Compose call carries `DOWNLOADINUX_NORDVPN_TOKEN`,
   including the running check; the C03 rule is only that the login's
   `NORDVPN_TOKEN` exists in that one process. The test asserts exactly
   that. Severity note; recorded as `brief-checklist §3`.
3. **target-design named the script the Done-when grep forbade** (report,
   *Doc inconsistencies* 3). The brief was wrong: the cut wrote
   `scripts/servers.py` into the C03 list and a Done-when that no doc may
   name it. The executor's fix (the old script, `downloadinux.servers`) is
   accepted. Severity note; an instance of `brief-checklist §2` (the cut
   did not grep its own doc edits for the retired source).
4. **`doctor`'s fourth arm** (`*` → could not read the settings) goes
   beyond the brief's three. Accepted: without it an unreadable config fell
   through to "malformed", which is false. Severity note.
5. **Decision bookkeeping skipped.** DEC-17 and DEC-18 are well formed and
   cited from target-design and the code, but the project header still said
   DEC-7 to DEC-16, the *Authority changes* table had no row for them, and
   the status file's *Decisions by chunk* had no C03 line. Fixed in this
