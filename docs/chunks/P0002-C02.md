# Chunk P0002-C02 — Reliable cookie export and setup refresh

**Source:** project [P0002](../projects/P0002-stage1-followups.md), delivery
item D2 (all of it), resolving
[#20](https://github.com/johnfoland/downloadinux/issues/20) and
[#26](https://github.com/johnfoland/downloadinux/issues/26). Authority:
[target design](../target-design.md) *Migration* ("Cookie and user-agent
follow-ups, pinned for P0002"); DEC-25.

**Goal:** `just cookies` publishes a newly exported Firefox jar only after it
has proved that this run produced usable Netscape output, while the fixed
YouTube probe may fail without turning a successful export into a failure.
Every setup path also attempts the user-agent refresh exactly once. A failed
or malformed export preserves the previous managed jar, so routine refreshes
are safe to retry. The pull request closes issues #20 and #26.

## Kickoff notes

- The staged jar, not an existing final jar, is the only evidence that this
  export succeeded; keep it in `paths.cookies` so publication is one rename.
- The probe's status and the export's usability are separate: a valid staged
  header wins, including when yt-dlp exits nonzero and when it has zero rows.
- Keep yt-dlp diagnostics visible, but never print a cookie value. A missing or
  malformed staged jar must not reach the count or user-agent steps.
- Setup's existing-session branch adds the refresh; its export branch gets the
  one refresh from `just cookies` and must not add another.

## Units

### P0002-C02-a — Stage, validate, and publish the Firefox jar
**Build:**
- Rework `just cookies [profile]` per target design *Migration*, "Cookie and
  user-agent follow-ups, pinned for P0002" (DEC-25). Keep the configured
  directory at mode 0700 and reserve a temporary name in that same directory.
  Arrange cleanup from the moment the temporary exists, then remove only that
  just-created empty entry before passing the now-absent path to yt-dlp's
  existing Firefox/profile export and fixed probe: yt-dlp reads an existing
  `--cookies` path before it writes it. Keep `umask 077`, and set the file
  yt-dlp creates to mode 0600 before validation and publication.
- Capture yt-dlp's status without letting `set -e` stop validation, and stop
  suppressing its diagnostics. Treat the stage as usable only when its first
  line is the Netscape cookie-file header; zero cookie rows are valid.
- For a usable stage, atomically rename it over `cookies.txt`, keep the final
  mode 0600, print the existing site-count summary, and invoke
  `just useragent` exactly once. If yt-dlp was nonzero, also warn that the
  probe failed but the exported jar was published, and do not fail merely for
  that probe status. Other failures, including a failed user-agent command,
  retain their ordinary nonzero status.
- For an absent or unusable stage, exit nonzero after cleanup without changing
  the previous jar, printing counts, or invoking the user-agent. Preserve the
  profile argument and never print cookie values or contents.

## Review

**Reviewed:** 2026-10-08. Verdict: **rework**. Verified: read every modified
non-test file in full and checked the focused tests against DEC-25, P0002 D2,
and every review-checklist entry; ran `just check` (all seven steps, 477 tests),
confirmed CI green on exact head `0cf6bb3`, and walked all four branch CI runs.
Also ran installed yt-dlp 2026.07.04 with pre-created empty and valid-header
`--cookies` files and inspected its installed cookie loader.

### Findings

1. **Blocking — the real cookie export cannot start** (`justfile:80-88`,
   `tests/test_cookies_recipe.py:19-56`; `review-checklist §2`,
   `brief-checklist §7`). The recipe passes yt-dlp the readable empty file
   created by `mktemp`. yt-dlp treats an existing `--cookies` path as an input
   jar before saving browser cookies and rejects that file as non-Netscape;
   the test stub instead overwrites it, so all 13 focused cases miss the real
   failure. Reserve the same-directory name securely but make that path absent
   when yt-dlp starts (or use an equivalent design that does not present an
   invalid input jar), retain cleanup from allocation onward, and ensure the
   created stage is mode 0600 before validation and atomic publication. Change
   the stub to reject a pre-existing empty stage and add an assertion that the
   real recipe supplies an absent output path; that test must fail on the
   reviewed implementation and pass on the rework without using a live browser
   or site.
2. **Note — the report landed before unit b's CI completed.** Commit `0cf6bb3`
   was created at 23:16 UTC while the run for `ddd6fe0` completed at 23:17 UTC.
   The unit and final-head runs were both green, so no code rework follows from
   this, but future unit commits should be allowed to finish green before the
   next lifecycle commit lands.
