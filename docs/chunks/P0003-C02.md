**Goal:** Finish P0003 D1 by exposing the tested source-store foundation through
automatic legacy migration and `cookies list`, `inspect`, and `default`.
Users can inspect their migrated account and choose the future named-source
default without a browser, Docker, or site request. This is additive preparation:
downloads, export, setup, and doctor retain the Stage 1 shared-jar behavior until
D4's coordinated cutover. Source: [issue #34](https://github.com/johnfoland/downloadinux/issues/34).
Reference #34 in the pull request; do not close it before D1–D5 are accepted.

## Units

### P0003-C02-a — Locked, idempotent legacy migration

**Build:**

- Add a reusable host migration/ensure-store operation taking the cookie root
  explicitly (§5, DEC-33). A valid existing registry is returned unchanged;
  malformed existing state is an operation error, never reset or repaired.
  When absent, take C01's host writer lock, recheck absence, and parse
  `<root>/cookies.txt` with the shared parser while holding the lock.
- A nonempty jar becomes file source `legacy`, with its absolute old managed
  jar path as refresh origin, a fresh immutable revision/UTC timestamp, and
  default `legacy` in one publication (§1, §5; DEC-28/DEC-33). Missing or valid
  header-only material commits an empty anonymous registry. Invalid/unreadable
  material publishes no registry and leaves the old jar unchanged; safe error
  text retains path/line/field where available and suggests repairing/moving
  aside the old jar before importing valid data, the repair alternative of §5.
  Do not suggest a runnable anonymous download flag before D4 implements it.
- Reuse/factor the writer transaction rather than copying atomic file logic
  or nesting exclusive lock acquisition (§1; DEC-24/DEC-27). Enforce existing
  0700/0600 managed modes, retain canonical revisions, and preserve allowed
  unreferenced/reservation residue when cleanup cannot establish ownership or
  remove it. Never chmod or overwrite either old jar. The reader itself still
  does not migrate; no existing command is wired to this operation yet.

**Tests:** Absent root/jar, valid empty jar, nonempty session/expired/HttpOnly
material, BOM/CRLF, malformed rows/UTF-8, normalized-domain duplicates
(review-checklist §4), and actual unreadable-file errors. Compare original
bytes and modes and inspect the committed canonical copy with the real parser.
Pin origin, default, modes, injectable revision/time, and no publication after
bad input. Repeated calls retain exact registry bytes/revision/timestamp;
an existing anonymous/named registry ignores even a corrupt old jar. Independent
processes with barriers prove one migration, locked absence recheck, no lost
existing registration/default, lock release after interruption, and no nested
lock deadlock (bounded process joins). Inject revision and registry publication
failures; previous committed state and old jars survive, and retry works after
the released lock. Reuse C01's atomic-writer oracle; when factoring publication,
hold migration and ordinary publication to the same writer semantics rather
than introducing a second implementation (review-checklist §1–§3).

**Done when:** migration yields exactly the specified complete store or a safe
operation error, is idempotent under real competing host processes, preserves
original files, and leaves all C01 writer/parser contracts passing. Focused
tests and the unchanged full `just check` pass.

### P0003-C02-b — Shared list/inspect/default operations and CLI

**Build:**

- Add shared host operations for `cookies list [--json]`, `cookies inspect
  NAME [--json]`, and `cookies default [NAME] [--anonymous]` (§2, §5). Resolve
  effective `paths.cookies` at the host boundary, then use unit a's ensure
  operation before source access. Keep CLI handlers as parsing/rendering fronts
  so the future TUI can call the same operations (*Host application*, DEC-7).
- Reuse `list_metadata`/`inspect` and their exact JSON fields, lexical ordering,
  clock injection, and secret-free summaries (§2; DEC-30). Human output renders
  the same source/count/domain/default information without cookie names/values
  or authentication claims. Empty lists succeed. `default` reports the name or
  `anonymous`; named/anonymous mutation goes through C01's locked default
  writer and changes no revision or refresh timestamp (§1–§2).
- Preserve global `--config`/repeatable `--set` placement/precedence at every
  parser level. Invalid source IDs and conflicting selectors are usage errors
  (exit 2); unknown valid IDs and OS/parse/store failures are operation errors
  (exit 1), through the established CLI error boundary (§2, *Host application*).
  Reject invalid syntax/selectors before running a cookie operation. No Docker,
  browser, credential, or user-agent operation is needed to inspect/select.
- Update README's implementation status, command reference, layout, and
  runnable migration/inspection/default examples; update the cookie README
  and planning implementation notes (§5). State prominently that these are
  preparatory commands: current downloads/export/setup/doctor still use the
  shared Stage 1 jar and do not follow this registry default. Do not document
  import/refresh/anonymous download flags as implemented. Recipe behavior and
  menu text stay unchanged because no new wrapper or cutover belongs here.

**Tests:** Drive all fronts through `cli.main` against temporary stores:
automatic legacy/empty migration, exact list/inspect JSON, lexical source/domain
order, injected expiry boundary, matching human metadata/counts, default report,
named selection, anonymous selection, and preserved revisions/timestamps.
Test unknown/invalid names, conflicting flags, damaged registry, missing or
malformed managed revision, actual filesystem failure, and bad legacy material;
assert exit status, path-bearing actionable errors, no traceback/cookie canary,
and no unintended state replacement (review-checklist §1–§3). Include BOM error
lines from the shared parser (review-checklist §5). Test global options before,
between, and after the nested subcommands with paths containing spaces and
XDG/custom settings. Block browser/Docker/credential access to prove host-only
operation. Pin `config show`'s lack of registry read/migration and existing
download/export/setup/doctor behavior, rather than activating any D4 route.

**Done when:** users can list/inspect migrated sources and report/set the
registry default through the specified CLI/shared operations; summaries and
errors satisfy §2, and current-user docs accurately distinguish this surface
from unchanged Stage 1 execution. D1's remaining evidence is in the report;
focused tests and all seven steps of `just check` pass.

## Notes for the executor

- Shared internal symbol names/placement are your choice; public commands,
  schemas, error statuses, lock/commit boundary, and summary fields are fixed.
- Migration absence is not `Path.exists()` swallowing unreadable input. Use
  actual read errors to distinguish missing material from operation failure.
- Do not call `initialize` first: that would commit anonymous state before
  legacy validation and prevent the one-time migration from selecting legacy.
- After migration, a later Stage 1 export can change the old jar without
  refreshing `legacy`; inspection intentionally keeps its immutable copy.
  This transitional fact is why D4 switches all execution/export routes together.
- Before each unit commit, run `just check`, record `just check: green` in its
  body, and wait for existing CI to pass before the next unit push. Keep branch
  history and record the two units and focused/full-gate evidence in the report.
