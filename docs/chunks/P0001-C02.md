# Chunk P0001-C02 — Container contract, Compose layer, and lifecycle commands

**Source:** project [P0001](../projects/P0001-portable-config.md), delivery
item D2 (first part), plus the follow-up from the P0001-C01 review (finding
1). Authority: [target design](../target-design.md) *Host application*
(including "Docker invocation, pinned for P0001-C02"), *Container contract*
(including "Compose files and the entrypoint"), *VPN mode* (its pinned
table), *Migration* ("Recipes when the Compose files change"); DEC-9,
DEC-11, DEC-15.

**Goal:** the container runs on the four-mount contract with its UID and GID
applied at start, from two Compose files the CLI drives with a computed
project, file list, and environment. `dlx build`, `up`, `down`, `restart`,
`update`, and `compose -- …` work from the settings file, VPN on or off, and
every `just` recipe reaches the container through the CLI, so the old
`docker-compose.yml` and its `.env` coupling are gone. Downloads keep working
unchanged through DEC-15's transitional links. The gate validates both
Compose configurations and smoke-tests the image VPN-off with temporary
mounts. D2's remaining commands (`shell`, `vpn`, `servers`, login on
`set-token`) and their wrappers follow in the next chunk.

## Kickoff notes

- **Master must keep downloading after this chunk.** Unit d deletes
  `docker-compose.yml`, so every recipe then goes through
  `uv run downloadinux compose --`; DEC-15's `/legacy/` binds and home links
  keep `just dl`, `batch`, and `useragent` writing to the host.
- **The token** reaches Compose only through the environment, only with the
  VPN on. Never run `compose -- config` without `-q` or a pipe into a
  checker: it prints the resolved token. Tests assert the fake token is
  absent from argv, and VPN off from the environment too.
- **No test runs Docker**: operations take an injectable runner. Docker runs
  only in the gate (config validation, the smoke script).
- **The entrypoint's ID change (unit c) is the risky part.** `usermod -u`
  rewrites ownership under `/home/dl`, so it runs before any link exists and
  no bind sits under `/home/dl`. The macOS gate runs it as UID 501, GID 20,
  which already exists in Debian: the group-reuse path.

**Review-checklist entries this chunk is likely to trip:**
`review-checklist §1`: every new filesystem and subprocess call (creating
`paths.state`/`paths.cookies`, a missing `docker`, missing Compose files)
must end as `downloadinux: error:` with exit 1, not a traceback.

## Units

### P0001-C02-a — OS failures through the error contract
**Build:**
- Every operation's `OSError` (creating a directory, reading or writing a
  file, `os.link`, and from unit b on, running `docker`) surfaces as a
  `DownloadinuxError` with exit 1 and a message
  `<path>: <reason>` (`strerror`), per *Host application*'s pinned list.
  Convert at the operation boundary or in `cli.main`, but the message must
  name the path.
- Sweep the existing operations for the same shape: `files.write_atomic`,
  `operations.store_token` (its read), `migrate.copy_jar` (mkdir, read, open),
  `migrate.import_env`'s writes.
**Tests:** through `cli.main`, with a read-only temporary directory (skip
when running as root, where permissions do not apply): `init`,
`config set-token`, and `config import-env` (settings file, and separately
the cookies directory) each exit 1 with `downloadinux: error:` naming the
path and no `Traceback` in stderr.
**Done when:** the tests pass; no command in the package lets an `OSError`
reach the user.

### P0001-C02-b — Compose files and the Compose layer
**Build:**
- `compose/base.yaml` and `compose/vpn.yaml` exactly as *Container contract*
  and *VPN mode* pin them, including the transitional `/legacy/` binds
  (DEC-15) in the base file. `presets/README.md` saying the presets move in
  with D3 (*Container contract*, pinned list).
- `src/downloadinux/compose.py` (suggested name): a function from effective
  settings and credentials to the `docker compose` argv prefix and
  environment (*Host application*, "Docker invocation"): project name,
  `--project-directory` the checkout root, the file list by `vpn.enabled`,
  inherited `DOWNLOADINUX_*` stripped except `DOWNLOADINUX_CONFIG` and
  `DOWNLOADINUX_IMAGE`, the variables of both tables set, `on`/`off` and
  `true`/`false` spellings, the token empty when unset or malformed. Compose
  files and `presets/` resolved through `checkout.asset_path`.
- `compose -- <args>` subcommand: `argparse.REMAINDER` after `--`, run through
  the injectable runner, exit with docker's status.
- Gate: step 5 (`docker compose config -q`) becomes two quiet validations
  through the CLI with a settings path that does not exist (so no real
  settings or credentials are read): `uv run --locked downloadinux --config
  "$tmp/absent.toml" compose -- config -q`, then the same with
  `--set vpn.enabled=true`. Step labels stay `N/7`. AGENTS.md *Commands*
  describes the new step and keeps the warning about printing the token.
**Tests:** VPN off: argv names only `base.yaml`, the project from
`container.project`, the project directory; the environment has every base
variable, no `DOWNLOADINUX_NORDVPN_*`, and the fake token nowhere in argv or
environment. VPN on: `vpn.yaml` added, the token in
`DOWNLOADINUX_NORDVPN_TOKEN` only, killswitch `on`/`off` and autoconnect
`true`/`false`, a malformed token passed as empty. A downloads path with a
space stays one argument/value. An inherited `DOWNLOADINUX_NORDVPN_TOKEN` is
removed when VPN is off; `DOWNLOADINUX_IMAGE` survives. A missing Compose file
is an exit-1 error naming it. `compose -- ps -a` passes `ps -a` through and
returns the runner's status. A test that the base file's interpolated
variables (`${…}` names, read as text) equal the table's set (plus
`DOWNLOADINUX_IMAGE`), and likewise for the overlay, so the files and the
CLI cannot drift.
**Done when:** the tests pass and both gate validations pass with the old
`docker-compose.yml` still present.

### P0001-C02-c — Image, entrypoint, and the smoke test
**Build:**
- Dockerfile: no `PUID`/`PGID`/`USERNAME` build arguments; user `dl` at
  UID/GID 1000, home `/home/dl`; no `config/` copies and no
  `/home/dl/Downloads` or `/home/dl/cookies` directories; `DL_USER=dl` kept
  for the zsh files; `WORKDIR /downloads` (*Container contract*, pinned list).
- `scripts/entrypoint.sh`: apply `DL_UID`/`DL_GID` as pinned (group reuse,
  UID clash stops with a message, skipped when unchanged); then create, as
  `dl`, `/downloads/dlmp4`, `/downloads/dlgal`, and the placeholder jar
  `/cookies/cookies.txt` (0600) when absent, warning on an unwritable mount;
  the zsh-history directory as today; then DEC-15's four links (`ln -sfn`,
  idempotent across restarts); `nordvpnd` only when `DL_VPN=on`. Messages
  that name `just shell` or `~/cookies` say the current path.
- `scripts/smoke.sh` (shellchecked by step 1) and a gate step 8/8 after the
  image build: temporary directories (the downloads one with a space in its
  name), a temporary settings path, project `downloadinux-check`,
  `DOWNLOADINUX_IMAGE=downloadinux:check`, VPN off; run
  `uv run --locked downloadinux … compose -- run --rm -T downloadinux sh -c
  '…'` and assert inside the container that `id -u`/`id -g` are the runner's,
  `/downloads/dlmp4`, `/downloads/dlgal`, and `/cookies/cookies.txt` exist,
  a file can be created and removed in `/downloads`, `/state`, and
  `/cookies`, `/config` is not writable, and `nordvpnd` is not running; on
  the host, that `dlmp4` exists in the temporary downloads directory. Also
  pipe `compose -- config --format json` of that VPN-off configuration into
  a `python3` check that the service has no `cap_add`, `devices`,
  `security_opt`, or `NORDVPN_*`/`DL_VPN` environment (D2 *Done when*).
  Clean up the project (`compose -- down -v`) and the temporary directories
  on exit, pass or fail. Gate labels become `N/8`; AGENTS.md lists the step.
**Tests:** the smoke step is the test. Gate mutations, each reverted: make
the entrypoint skip creating `/downloads/dlgal` (smoke fails), and add
`cap_add: [NET_ADMIN]` to the base file (smoke fails).
**Done when:** `just check` passes with 8 steps locally (macOS, UID 501,
GID 20) and in CI (Linux), leaving `git status --porcelain` empty and no
`downloadinux-check` container or volume behind.

### P0001-C02-d — Lifecycle commands and recipe rewiring
**Build:**
- `build`, `up`, `down`, `restart`, `update` subcommands per *Host
  application*'s "Docker invocation" list: the downloads check and the
  `paths.state`/`paths.cookies` creation (0700 for cookies) before `up`,
  `restart`, and `update`; exit 1 when `docker compose` fails.
- The justfile per *Migration*, "Recipes when the Compose files change":
  `compose` and `dex` variables through the CLI; lifecycle and `token`
  recipes as wrappers; `batch` from `paths.downloads`; `cookies`, `setup`,
  and `doctor` on `paths.cookies`/`cookies.txt`; `setup`'s `import-env`
  step. A small shell helper that reads one key from `config show --json`
  with `python3` is fine; no new CLI command. Recipe comments (the menu
  text) say what each now does; `restart` no longer mentions `.env`.
- Delete `docker-compose.yml`. Nothing in the repo may still reference it
  except history in docs.
- README.md: the host CLI section gains the lifecycle commands and
  `compose`; the setup and daily-use text says the recipes now read the
  settings file, that an existing install runs `dlx config import-env` once
  before its next `just up`, and where the cookie jar now lives;
  `cookies/README.md` says the jar moved to the managed directory and the old
  file is no longer read.
**Tests:** with a fake runner: `up` with a missing downloads directory exits
1 naming it and runs nothing; `up` creates state and cookies (0700) and runs
`up -d`; `restart` runs `up -d --force-recreate`; `update` runs
`build --no-cache` then `up -d`, and stops after a failed build; a non-zero
runner status makes a lifecycle command exit 1; `docker` not found exits 1
with `downloadinux: error:` (`review-checklist §1`). A test that greps the
justfile for `docker compose` and `docker-compose.yml` and finds neither.
**Done when:** the tests pass, the gate passes, and by hand (recorded in the
report, VPN on from an imported config): `just up`, `just dl video <a public
URL>` lands under the host `paths.downloads`/`dlmp4`, `just restart`, and
`just down` work; `just cookies` writes the managed jar.

## Notes for the executor

- `--project-directory` is the checkout root, so the base file's build
  context is `.` and its legacy binds are `./config/yt-dlp` and
  `./config/gallery-dl`; the other bind sources come from variables.
- Compose reads a `.env` in the project directory for interpolation. It is
  harmless only because nothing in the new files uses an unprefixed name;
  keep it that way, and keep the variable-set test from unit b honest.
- `compose -- run` executes the entrypoint, which ends in
  `exec gosu dl "$@"`, so the smoke command already runs as `dl`.
- The smoke test's cleanup must not touch the default `downloadinux` project
  or its volumes: it names `downloadinux-check` everywhere.
- Docker Desktop's bind mounts on macOS report host ownership loosely; the
  host-side ownership assertion is "exists", the UID/GID assertions are made
  inside the container.
