# Chunk P0002-C01 — Portable atomic no-clobber writes

**Source:** project [P0002](../projects/P0002-stage1-followups.md), delivery
item D1 (all of it), resolving [issue #14](https://github.com/johnfoland/downloadinux/issues/14).
Authority: [target design](../target-design.md) *Host application*
("Portable no-clobber writes, pinned for P0002"), *Configuration and paths*
(the `init` contract), and *Migration* (the `config import-env` no-overwrite
contract); DEC-24.

**Goal:** settings and credentials writes that refuse to clobber an existing
file continue to publish atomically on filesystems that reject hard links,
without weakening the race boundary or cleanup guarantees. `dlx init` and
`dlx config import-env` then work at supported custom config paths such as
exFAT or FUSE while retaining their current modes, messages, and `--force`
behavior. The pull request closes issue #14.

## Kickoff notes

- Keep the hard-link publication as the preferred path; only the three
  link errors named by DEC-24 select the reservation fallback.
- The difficult case is cleanup after the reservation exists: compare the
  directory entry's device and inode with the recorded reservation and never
  remove a replacement created by another actor.
- Preserve the existing synced same-directory temporary, final file modes,
  target-path error rewriting, and `replace=True` behavior.
- `config import-env` has two no-clobber outputs when it imports a token.
  Its settings call is already race-safe; its credentials call must gain the
  same `replace=force` boundary and the same established refusal message.
- Tests use fault injection, not a special filesystem, and must model the real
  `os.link`, `os.open`, `os.fstat`/directory-entry stat, and `os.replace`
  outcomes closely enough to exercise the races rather than just the mocks.

## Units

### P0002-C01-a — Portable reservation fallback
**Build:**
- Extend `files.write_atomic(..., replace=False)` per target design *Host
  application*, "Portable no-clobber writes, pinned for P0002" (DEC-24).
  After the existing synced same-directory temporary is complete, try the
  hard link first. Only `EPERM`, `EOPNOTSUPP`, or `ENOTSUP` from that link
  attempt may reserve the target with `O_CREAT | O_EXCL` at mode 000, record
  the reservation's device and inode, close it, and atomically replace that
  reservation with the temporary file.
- Keep `FileExistsError` and every unrelated link error on the existing
  failure path. On any failure after reservation, remove the target only
  while the directory entry is still the recorded reservation; a missing or
  replaced entry is not this operation's to remove. Keep temporary cleanup,
  target-path error reporting, `replace=True`, and the successful hard-link
  path unchanged.
- Update the module and function documentation to cite DEC-24 and describe
  both publication paths without promising cleanup of a reservation left by
  a killed process.

**Tests:** Extend the direct `files.write_atomic` and OS-error coverage. For
each supported link errno, prove the fallback publishes the complete text at
the requested mode, uses an exclusive mode-000 reservation, and leaves only
the target. Prove an existing target is unchanged; an unrelated link error
does not attempt the fallback and is reported against the target; a replace
failure removes the owned reservation and temporary; and cleanup preserves a
target that a test actor swaps to another inode before the failure is handled.
The injected `os.link` error must match the real call as required by
`review-checklist §2`.

**Done when:** both publication paths produce the same complete file and
mode, every failed path leaves no temporary or still-owned reservation where
the OS permits cleanup and ownership can be verified (DEC-27), a
foreign replacement survives cleanup, unsupported errors retain their
meaning, and the focused tests plus `just check` pass.

### P0002-C01-b — No-clobber callers and command evidence
**Build:**
- Apply the shared no-clobber publication to every creation path that already
  passes `replace=False`: `init`, non-forced settings import, and a missing
  settings file written by `config user-agent`. Preserve their existing
  success and refusal contracts.
- Make the credentials write in non-forced `config import-env` no-clobber too:
  pass `replace=force`, translate a credentials `FileExistsError` to the
  existing `<credentials path> already exists; use --force to overwrite it`
  operation failure, and leave a racing file byte-for-byte unchanged.
  Forced import continues to atomically replace both files.
- Update README.md's configuration or migration guidance with the user-facing
  result: selected config paths on filesystems without hard-link support keep
  atomic, no-clobber creation. Do not expose the reservation mechanics there.

**Tests:** Drive real CLI entry points with OS-boundary fault injection.
`init` and `config import-env` without `--force` succeed when the link step
raises each supported errno; imported settings and credentials contain the
expected TOML and keep their existing modes. Inject a target appearing at
exclusive reservation for settings and credentials separately and assert
exit 1, the established target-path message, unchanged racing bytes, no
temporary or owned reservation, and no traceback. Keep the existing
`--force` replacement test and add only the assertion needed to prove it does
not take the no-clobber branch. Cover the missing-file `config user-agent`
path at the focused operation level if the direct writer tests alone do not
show that caller using the fallback.

**Done when:** `init` and non-forced import work through the fallback without
clobbering a pre-existing or racing settings or credentials file; forced
import still replaces both; modes, TOML, paths, messages, and cleanup match
the current contracts; issue #14 is named with `Fixes #14` in the pull
request; and `just check` passes.

## Notes for the executor

- `errno.EOPNOTSUPP` and `errno.ENOTSUP` may alias on a platform. Exercise the
  named contract without making the suite depend on their numeric values
  being distinct.
- Record the reservation identity from its open file descriptor; compare it
  with the directory entry without following a final symlink. This makes the
  ownership check about the name that would be unlinked, not a symlink target.
- Keep cleanup local to the writer. Callers should only translate
  `FileExistsError` into their established command-specific wording.

### Decisions made

DEC-27: preserve a reservation whose identity cannot be verified; report
cleanup failures and still attempt descriptor/temporary cleanup. This keeps
DEC-24's ownership boundary when the OS itself fails.
