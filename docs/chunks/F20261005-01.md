**Goal:** the repo gets one command, `just check`, that statically checks
every script and config it can and builds the image, and a GitHub Actions
workflow that runs exactly that command on every pull request and push to

## Kickoff notes

The gate's steps and their order are pinned below (unit b); don't add or drop
one. Three things are easy to get wrong:

- **Secrets.** `set dotenv-load` loads `.env` (with the NordVPN token) into
  every recipe's environment. `docker compose config` without `-q` prints the
  resolved file, token included. Only ever run it with `-q`, and never echo
  the environment.
- **Fail, don't skip.** If the Docker daemon is unreachable, `just check`
  exits non-zero with a message saying so. A gate that quietly skips the build
  reports green while checking less.
- **Gate = CI.** The workflow installs tools and then runs `just check` and
  nothing else, so the two can't drift. Tool versions in CI match the local
  ones (just 1.40.0 from `.tool-versions`, shellcheck 0.11.0).

Unit a changes `scripts/entrypoint.sh`, which runs at every container start:
keep its behavior identical, including which branch logs or warns.

### F20261005-01-b — `just check`
**Build:** a `check` recipe in `justfile` (a `#!/usr/bin/env bash` recipe with
`set -euo pipefail`), placed in the section with `build`/`up`, with a menu
comment such as "Static checks and an image build (the CI gate)". It runs
these steps in this order, printing a one-line label before each, and stops at
the first failure:
1. `shellcheck scripts/*.sh`
2. `zsh -n` on each of `zsh/zshrc`, `zsh/aliases.zsh`, `zsh/functions.zsh`,
   `scripts/root.zshrc` (syntax only; shellcheck doesn't support zsh).
3. Compile `scripts/servers.py` without writing bytecode into the checkout:
   `python3 -c 'import sys; compile(open(sys.argv[1]).read(), sys.argv[1], "exec")' scripts/servers.py`,
   not `py_compile` (that leaves `scripts/__pycache__/`, which nothing
   ignores).
4. `docker compose config -q`, the `-q` mandatory (see kickoff notes).
5. A daemon check, `docker info >/dev/null 2>&1`, that on failure prints
   "Docker daemon not reachable — start Docker and re-run" to stderr and exits
   1.
6. `docker build --tag downloadinux:check .`: a separate tag, so the gate
   never replaces the `downloadinux:latest` image that `just up` runs. No
   `--no-cache`.
Then print a single success line. The recipe must not read or print `.env`,
must not need a `.env` to pass, and must leave `git status --porcelain`
unchanged.
**Tests:** `just check` exits 0 on the branch; `git status --porcelain` is
empty afterwards. Then prove each step can fail, reverting each mutation:
add an unquoted `$1` use to `scripts/vpn.sh` (step 1 fails); add an unclosed
`if` to `zsh/aliases.zsh` (step 2); add a syntax error to
`scripts/servers.py` (step 3); misspell a top-level key in
`docker-compose.yml` (step 4); and with the daemon stopped, or with
`DOCKER_HOST=unix:///nonexistent`, step 5 fails with its message. Each must
exit non-zero. Also run it with `.env` moved aside, then restore it. Record
the results in the report.
**Done when:** `just check` passes on a clean tree, fails on each mutation
above, and leaves no files behind; `just` (the menu) lists it.

## Notes for the executor

- `docker compose config -q` needs no daemon; the build does. That's why the
  daemon check sits between them.
- If `docker build` fails for a network reason (NodeSource, the Nord apt repo,
  pip), retry once; if it keeps failing, stop and report rather than
  weakening the step.
- Consider the CI job's install steps carefully against the runner; a
  shellcheck tarball install is `curl -fsSL …/shellcheck-v0.11.0.linux.x86_64.tar.xz | tar -xJ`
  then putting the binary on `PATH` (`$GITHUB_PATH`).
