# Chunk P0001-C04 — Presets, downloads, and the end of the legacy paths

**Source:** project [P0001](../projects/P0001-portable-config.md), delivery
item D3 (all of it), plus findings 1 and 6 of the P0001-C03 review (issues
#17 and #18). Authority: [target design](../target-design.md) *Host
application* ("Commands in the container, pinned for P0001-C03", for the
hint; "Downloads, pinned for P0001-C04"), *Container contract* and
*Presets* ("pinned for P0001-C04"), *Migration* ("Pinned for P0001-C04");
DEC-6, DEC-10, DEC-13, DEC-15, DEC-19, DEC-20, DEC-21.

**Goal:** downloads run through the CLI. The two downloader configs become
read-only presets under `presets/` holding media behavior only, and
`dlx dl`, `dlx batch`, and `dlx watch` give them their output root,
cookies, user-agent, and archive as arguments from the settings.
`dlx config user-agent` writes the user-agent into the settings file
instead of rewriting tracked files, so routine operation leaves the
checkout clean. DEC-15's interval ends: no `/legacy/` binds, no home links,
no `config/` directory. The container's `dlmp4`/`dlgal` helpers follow the
presets, and the batch loop starts without interactive zsh. With D3 done,
D4 (structured health checks) is next.

## Kickoff notes

- **The argument lists are pinned element by element** (*Presets*): no
  `--ignore-config`, no `-w`, no reordering; the user-agent is one element.
- **Unit c is the heavy one.** `git mv` the configs, strip only the pinned
  lines (the review reads the rename diff), and drop the `/legacy/` binds
  in the same commit: a bind on a missing source stops the smoke test.
- **Every reader of the retired paths moves here**; the Done-when greps are
  the check. `doctor` changes only its two pinned lines (D4 owns the rest).
- **The zsh helpers are a second implementation** of the lists (unit d);
  the test runs them under real `zsh` against the package's lists.
- **Manual checks use throwaway directories**: the gallery archive applies
  to every extractor, so a test download would write the real archive.

**Review-checklist entries this chunk is likely to trip:**

## Notes for the executor

- The write test: `sys.addaudithook` sees every `open` (the event carries
  path, mode, and flags; `os.open` passes flags). Install one hook for the
  session, gated by a flag the test sets, and fail on a write-mode open
  under the checkout's `presets/` while each operation runs with fake
  runners (`init`, `config show`, `set-token`, `import-env`,
  `user-agent`, `dl`, `batch`, `watch`, the lifecycle commands). Audit
  hooks cannot be removed, which is why it is gated.
- `zsh` is already on CI (the gate's step 2), so the helper test may run
  it; it must fail, not skip, when `zsh` is missing.
- Aliases are expanded where they are used, so `dlmp4` can be an alias
  whose body refers to `$DL_USER_AGENT`; a function per preset that the
  aliases and the batch wrappers both call keeps the words in one place.
  Either shape is fine as long as the test holds it to the package.
- `gallery-dl -o` parses each value as JSON first and falls back to the
  string; the pinned values are not JSON, so they stay strings.
- `just` runs recipes in the checkout, so a relative queue given to
  `just batch` resolves against the checkout, as it does today; the CLI
  resolves against its own working directory.
